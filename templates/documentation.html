Functional Overview

Scope & Audience

ARSINOE integrates weather forecasts, Sentinel-2 NDVI, and AquaCrop simulations for the Sardinian pilot sites Ussana and Benatzu. It offers both human-readable views and a REST API designed for agronomic decision support, research reproducibility, and automated pipelines.

Data Sources

  • Open-Meteo (GFS): ensemble forecasts (seamless) and historical archive.
  • Sentinel-2 L2A: NDVI raster and Scene Classification (SCL) for quality filtering.
  • Local GIS layers: parcel polygons for per-parcel NDVI statistics and map overlays.

Weather Forecasts (GFS via Open-Meteo)

The platform retrieves short- to medium-range forecasts from Open-Meteo (GFS seamless ensemble and archive), building hourly and daily aggregates for temperature, precipitation, ET0 FAO evapotranspiration and wind speed. These data drive ensemble visualizations (e.g., boxplots of members with control run overlays) and provide the meteorological forcing for crop simulations.

Sentinel-2 & NDVI

A local catalog of Sentinel-2 scenes is maintained for the study areas. New scenes are downloaded only when missing, including NDVI and SCL. Per-parcel NDVI statistics (mean/min/max/std) are computed using the parcel shapefile; a Leaflet/Folium view overlays the latest NDVI (fixed 0–1 color scale) with boundaries and tooltips.

AquaCrop Simulations

Users upload weather inputs and run AquaCrop for the selected site (Ussana/Benatzu). Results are saved as JSON, and a Plotly figure is returned with yield indicators versus harvest date. In the ensemble workflow, historical daily data (archive) can be merged with the ensemble forecast window; an optional debias step aligns means on the overlap (temperature, precipitation, ET0) before running across members.

Water-Profile (Ensemble) Outputs

The AquaCrop ensemble produces two PNGs per site/day: (i) multi-layer soil water profile with median and inter-quantile bands (10–90, 25–75); (ii) an overview of key variables (e.g., canopy cover, biomass, harvest index, fluxes). Outputs are cached by date and site and reused unless recomputation is forced.

Digital Twin

For each campaign year, the service exposes available parameter keys and corresponding time series, enabling downstream analysis and visualization.

Caching & Reproducibility

  • Weather: client-side caching on requests; archive/forecast windows are stitched deterministically.
  • Satellite: scenes downloaded once; NDVI/SCL products stored under static directories.
  • AquaCrop: results and images are saved under predictable filenames (site+date); use force=true to recompute.

Usage Notes

  • Use Swagger UI to try endpoints interactively, inspect parameters and response schemas.
  • Use ReDoc for a structured, read-only reference with longer descriptions.
  • Many visual endpoints return Plotly JSON; render with Plotly.newPlot(...) on the client.
  • Cache behavior: satellite scenes and ensemble outputs are reused if present; pass flags (e.g., force=true) to regenerate.

For issues or feature requests, please contact the project maintainers.
